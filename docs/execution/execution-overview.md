# Execution Engine Overview

The Execution Engine is the execution substrate of usePilot. It consumes immutable `ExecutionBlueprint`s generated by the Phase 2 Planning Engine and executes them deterministically without LLM intervention during normal operation.

## Core Principles

1. **Deterministic Execution**: The planner produces the blueprint; the runner executes it. No re-planning or LLM prompting occurs in the execution loop.
2. **Capability Abstraction**: Tasks specify abstract `TaskCapability` requirements (e.g. `navigate_website`, `read_file`), resolved to concrete adapters via `CapabilityRegistry`.
3. **Resumable & Crash-Resistant**: Execution state is checkpointed at batch boundaries and before human approvals. A restarted run resumes without re-executing completed tasks.
4. **Append-Only Audit Journal**: Every state transition, adapter invocation, verification result, and retry is written to an immutable SQLite journal.
5. **Rigorous Verification**: A task is never marked complete simply because an adapter executed without error; the `VerificationEngine` independently verifies postconditions and success criteria.

## Lifecycle Flow

```text
Validated ExecutionBlueprint
            │
            ▼
     TaskScheduler
 (reads Phase 2 DAG batches)
            │
            ▼
     ExecutionRunner ───► CapabilityRegistry ───► ICapabilityAdapter
            │                                           │
            ├───► ApprovalGate (human-in-the-loop)      ▼
            ├───► RetryEngine ─────────────────► VerificationEngine
            ├───► ExecutionStateMachine
            ├───► CheckpointManager ───────────► SQLite Checkpoints
            └───► ExecutionJournal ────────────► SQLite Journal
            │
            ▼
     ExecutionResult & ExecutionReport
```
